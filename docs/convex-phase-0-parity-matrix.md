## Phase 0 gaps

Production-scale file parsing, twice-largest capacity, reactive behavior, Clerk-backed Convex authentication, and scheduler behavior belong to later Convex phases and require a real development or preview deployment.

## Reusable synthetic oracle

`packages/importers/src/golden-fixtures.ts` exports fake source files and exact semantic parser outputs for Tickertape stocks, Tickertape mutual funds, NPS portal CSV, the investment workbook, and the Vested/DriveWealth workbook. Tests compare the entire `ParseResult`, so parser warnings, metadata, currencies, and NPS details cannot drift unnoticed. Generated workbooks are created in memory and no fixture contains production names, account numbers, or values.

`packages/analytics/src/golden-fixtures.ts` exports exact expected portfolio-performance results for cash-flow XIRR, source-XIRR fallback, valuation-history fallback, and insufficient history. These are public typed fixture builders so the Phase 2 publication module and Convex query tests can consume the same oracle instead of copying expected values.

The current Postgres integration suite provides the publication-level oracle for same-date NPS/workbook priority, cross-source partial imports, aggregate/detail fallback, exit/re-entry, identity concurrency, holding/NPS detail, INR/USD aggregation, file lifecycle, and import history. Semantic assertions use stable names, symbols, dates, values, statuses, and currencies rather than generated IDs.

## Current-model boundaries

- `NormalizedImportRow` has no explicit complete/partial snapshot or source-group contract. The current executable boundary proves that a different-source partial import preserves workbook positions and that omission within a later same-source import exits a position. Phase 2 must introduce explicit completeness/source metadata and run `source_group_partial_import_membership` plus `complete_snapshot_exit_and_reentry` before treating arbitrary omissions as exits.
- Transactions have no source occurrence identifier. The current executable boundary (`import-service.integration`: “commits transaction rows and dedupes a re-import of the same trade”) deliberately preserves the existing fingerprint behavior, which collapses otherwise identical occurrences. Phase 2 must add occurrence identity and run `identical_same_day_transaction_occurrences`; this is a named reconciliation check until that contract exists.
- Fresh, stale, and unavailable FX states are service-level oracles because the current public portfolio query fetches the rate internally. Phase 2 query golden tests must inject these three rate states and run `usd_inr_fresh_stale_unavailable` against the published mixed-currency read model.
